\# System Planning



\## Purpose



The purpose of the system plan is to organize the main parts of the proposed application before development begins. The system will be divided into separate modules so that citizen requests, municipal processing, administration, and reporting can be managed clearly.



\## Main System Modules



\### 1. User Management



This module will manage registration, login, user roles, and access permissions. The main roles will be Citizen, Municipal Officer, Department Supervisor, and System Administrator.



\### 2. Service Request Management



This will be the main module of the system. Citizens will be able to submit municipal problems by selecting a category, adding a description, providing a location, and attaching a photo when available. Each successful request will receive a unique tracking ID.



\### 3. Request Processing



Municipal officers will use this module to review incoming requests, assign them to the appropriate department or field team, update progress, add notes, record delays, and complete requests.



\### 4. Tracking and Notification



Citizens will be able to track the progress of their requests. The system will show information such as the current status, responsible department, expected resolution time, and important updates. Notifications can also be sent when major status changes occur.



\### 5. Escalation Management



Requests that remain unresolved beyond their expected time can be identified for further review. Department supervisors will be able to view these cases and take appropriate action.



\### 6. Feedback Management



After a request is resolved, citizens will be able to provide feedback about the service and indicate whether the reported problem was properly addressed.



\### 7. Reporting and Monitoring



Supervisors and administrators will be able to view basic reports such as the number of submitted, pending, resolved, and delayed requests. Reports can also help identify frequently reported problems and compare service performance between departments.



\### 8. Administration



System administrators will manage departments, service categories, user roles, permissions, and other basic platform settings.



\## Basic Service Workflow



The basic request process will follow these steps:



1\. A citizen submits a service request.

2\. The system records the request and generates a tracking ID.

3\. The request is reviewed and routed to the responsible department.

4\. An officer or field team is assigned.

5\. The request status is updated while the work is in progress.

6\. Any delay or important progress information is recorded.

7\. After the work is completed, resolution details are added.

8\. The request is marked as resolved.

9\. The citizen receives the final update and can provide feedback.



This workflow keeps the request visible from the time it is submitted until the final resolution.
