\# Non-Functional Requirements



\*\*NFR-01 — Security\*\*

The system should protect user accounts and sensitive information from unauthorized access.



\*\*NFR-02 — Privacy\*\*

Personal information, complaint details, and user location data should only be accessible to authorized users when required.



\*\*NFR-03 — Usability\*\*

The system should have a simple and clear interface so that citizens with different levels of technical knowledge can use it easily.



\*\*NFR-04 — Performance\*\*

Common actions such as submitting a request, checking status, and opening dashboards should respond within a reasonable amount of time.



\*\*NFR-05 — Availability\*\*

The system should remain available as much as possible so citizens can submit and track requests when needed.



\*\*NFR-06 — Accessibility\*\*

The interface should be designed so that elderly users and people with different accessibility needs can use the main services.



\*\*NFR-07 — Mobile Compatibility\*\*

The system should work properly on smartphones as well as desktop and laptop browsers.



\*\*NFR-08 — Reliability and Data Backup\*\*

Submitted requests and important system data should be stored reliably and backed up to reduce the risk of data loss.



\*\*NFR-09 — Scalability\*\*

The system should be able to handle an increasing number of users and service requests as more citizens begin using the platform.



\*\*NFR-10 — Auditability\*\*

Important actions, such as status changes, assignments, and resolution updates, should be recorded so that the service history can be reviewed when necessary.
